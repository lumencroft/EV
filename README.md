# EV (Elevator) Recognition System for Robot Navigation

## 프로젝트 개요
이 프로젝트는 로봇이 엘리베이터에 탑승할 때, 내부의 혼잡도를 파악하고 문 열림 상태를 파악하여 안전하게 탑승할 수 있도록 지원하는 비전 기반 AI 시스템입니다. NVIDIA Jetson Orin Nano와 같은 엣지 디바이스 환경에서 TensorRT를 활용해 실시간 추론을 수행하며, 로봇 제어부(HMI)와 UDP 통신을 통해 탑승 가능 여부(GO/STOP)를 제어합니다.

## 핵심 성과 및 문제 해결 (Key Achievements)
* **환경적 특성을 활용한 직관적인 문 개폐 감지**: 원거리 대기 조건 및 문의 구조적 단차로 인해 라이다(LiDAR)와 뎁스(Depth) 센서 활용이 제한적인 상황이었습니다. 이를 해결하기 위해 '엘리베이터 내부 천장 조명'이라는 보편적인 환경 요소에 착안했습니다. 조명의 밝기 픽셀 변화(ROI)를 분석하는 직관적인 로직을 도입하여, 무거운 모델 없이도 가볍고 범용적인 개폐 감지 시스템을 구현했습니다.
* **3D 복원에서 2D 기하학으로 혼잡도 알고리즘 경량화**: 기존에는 혼잡도 파악을 위해 뎁스 데이터 기반의 무거운 3D 복원(3D Reconstruction) 연산이 고려되고 있었습니다. 프로젝트 합류 후 단 3일 만에, 뎁스 맵에 등고선(Contour)을 그리고 볼록 선체(Convex Hull)와의 면적비(용적률)를 구하는 2D 기하학 방식으로 알고리즘을 재설계했습니다.
* **시스템 최적화**: 이러한 구조 개편을 통해 제한된 리소스를 가진 Jetson 엣지 환경에서도 연산 부하를 최소화하며, 빠르고 안정적인 실시간 인퍼런스 파이프라인을 구축할 수 있었습니다.

## 주요 기능 및 특징
* **조명 기반 문 열림 감지**: 엘리베이터 특정 관심 영역(ROI) 내 조명의 밝기 임계값(Threshold)과 픽셀 면적 비율을 분석하여 문의 개폐 상태를 감지합니다.
* **엘리베이터 내부 혼잡도 산출**: Depth-Anything 모델을 기반으로 뎁스 맵(Depth Map)을 생성한 후, 다중 뎁스 레벨에 따른 등고선과 볼록 선체의 면적 비율을 수치화하여 사람 및 장애물 밀집도를 산출합니다.
* **실시간 UDP 통신 제어**: 10프레임 동안 연속해서 탑승 가능(GO) 판정이 5회 이상 유지될 때 로봇 HMI(192.168.1.30) 측으로 최종 제어 명령 패킷을 반환하여 주행 안정성을 확보했습니다.

## 시스템 아키텍처 및 동작 흐름
1. **대기 (Standby)**: HMI 시스템으로부터 엘리베이터 인식 시작 신호 대기.
2. **캡처 및 추론 (Capture & Inference)**: 웹캠 프레임을 획득하고 TensorRT 기반 Depth 모델 추론 및 ROI 조명 감지 병렬 수행.
3. **판단 (Decision)**: 도출된 뎁스 맵 혼잡도 점수(Occupancy Score)와 문 열림 상태를 결합하여 최종 탑승 여부 판단.
4. **결과 피드백 (Feedback)**: 산출된 상태를 UDP 패킷으로 HMI에 전송.

## 환경 설정 (Environment)
* **Target Device**: NVIDIA Jetson Orin Nano
* **네트워크 구성**:
  * Jetson AI (Host): `192.168.1.21` (Port: 5001)
  * Robot HMI: `192.168.1.30`

## 파일 구성 및 역할 (File Description)
### 핵심 로직 모듈
* **`main_comm.py`**: 비전 데이터 수집, 혼잡도 판단, 네트워크 통신 등 전체 사이클 제어 (서비스 자동 실행).
* **`depth.py`**: TensorRT(`depth.engine`)와 PyCUDA를 활용한 고속 Depth Estimation 추론 모듈.
* **`occu.py`**: 뎁스 맵 기반 등고선 추출 및 Convex Hull 면적비 알고리즘을 통한 혼잡도 연산 모듈.
* **`door.py`**: 엘리베이터 천장 조명의 밝기를 이용해 문 열림 상태를 1차적으로 감지하는 비전 처리 모듈.
* **`commu.py`**: HMI와의 UDP 통신 전담 (프로토콜 파싱 및 상태 송수신).

### 시스템 및 배포 스크립트
* **`create_service.sh`**: `main_comm.py`를 systemd 기반 백그라운드 서비스(`EV_recognition.service`)로 등록.
* **`setnetwork.sh`**: Jetson 보드의 이더넷 IP(`192.168.1.21/24`) 고정용 네트워크 셋업.
* **`depth.engine`**: TensorRT 추론 가중치 파일 (Jetson Orin Nano 타겟).

### 디버깅 모듈
* **`depth_test.py`**, **`door_test.py`**, **`commu_test.py`**: 혼잡도 시각화, 조명 감지 상태, 통신 패킷을 독립적으로 검증하기 위한 테스트 스크립트.

## 운용 환경의 제약 및 극복 로직 (Operational Constraints & Solutions)
본 프로젝트는 서비스 로봇의 특성상 하차객의 동선을 방해하지 않기 위해 엘리베이터 정면이 아닌 원거리에서 대기해야 하는 물리적 제약이 존재합니다. 이로 인해 로봇 하단의 라이다(LiDAR) 센서 활용이 불가능하고, 움푹 패인 문의 구조적 한계로 단안 카메라의 상대 뎁스(Relative Depth) 역시 판별에 활용하기 어려웠습니다. 또한 HMI와의 통신망 불안정 이슈까지 겹쳐 타이머 기반 우회(Bypass) 주행조차 불가능한 상황이었습니다. 

이러한 사각지대를 돌파하기 위해, 복잡한 하드웨어 센서나 불안정한 외부 네트워크에 의존하는 대신 원거리 카메라 영상을 분석하는 독자적인 소프트웨어 경량화 솔루션(`door.py`, `occu.py`)을 설계하여 제약을 극복했습니다.
